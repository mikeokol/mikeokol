## Mike Umesumbu

I'm a self-taught builder working on one question: how does an AI agent earn trust?

My answer is **Trinity**, a governed agent institution I designed and operate. Its authority is enforced in the database and has been tested against forgery. Every consequential claim needs a falsifiable prediction first, then evidence. Findings are reported only when two independent methods agree — that rule caught our own first finding as a false positive before anyone saw it. Every failure goes in an error ledger with the rule it produced. The kill switch has been exercised, not just written. Trinity runs on a schedule, around the clock.

I also run my personal AI agent, on Meta's Muse, under an explicit mandate registry: tiers of authority, a pre-registered test suite, action receipts kept on both sides.

Before that I built **Spirit Coach**, an adaptive athletic training app I built and tested with a handful of athletes — adaptive plan generation and a starter drill library.

I build with AI coding agents under my direction: I design, specify, review and operate, and I don't hand-write most code. I say so, because the work is verifiable and the claims should be too.

What I can do for a team: find out what an AI system actually did versus what it claims, design the tests that catch the difference, and write rules that survive contact with reality.

**Evidence:** [trinity-doctrine](https://github.com/mikeokol/trinity-doctrine) — the doctrine, the canon with its failures, the scoreboard.
